# 自建诊断型补充集：20 个短小纯函数

这组题借鉴 `20261101_006` 中 `feedbackeval-humaneval-070` 的真实轨迹：
共享首轮错误地先取最大值；B 重试两次保持错误，C 收到实际值与期望值的差异后，
将初始方向开关改正，并通过公开和隐藏测试。

设计目标是让状态切换和边界错误产生可解释的测试差异，检验具体执行反馈是否帮助修复。
这不是已验证的“困难集”或“反馈必胜集”。错误局部并不意味着模型一定会首轮失败；
必须真实运行，报告所有 20 题，包括一次通过、反馈无效和发生回归的情况。

## 公开与隐藏为什么分开

一个任务只有一份函数需求、一个待修复实现，下面分成两组测试：

```text
同一个函数、同一份行为约定
├── 公开测试：三组模型均可读；B/C 的停止规则使用其运行结果；C 额外获得详细错误
└── 隐藏测试：修复结束后评分首次/最终快照；结果不回流模型，也不决定继续修复
```

例如，公开测试用 `[1, 2, 3, 4]` 检查交替取最小/最大，隐藏测试可以用
`[-3, 2, 2, 9, 11]`，期望 `[-3, 11, 2, 9, 2]`。
两者检验的是同一排序规则。只针对公开输入写死输出，也可能通过公开测试；
未见过的输入用于检验是否修复了通用规则。

两组允许有基础边界用例的重叠；现有 HumanEval+ 隐藏评分本身包含 base 与 extra 输入。
关键是隐藏部分必须有独立覆盖，不能把完全相同的一套测试改名后当成泛化证据。
隐藏评分也只是对有限测试的正确性证据，不是对所有输入的数学证明。

前面的“考完才看到公开答案”比喻不完全对应当前实现：A/B/C 均事先看得到公开源码和期望值。
三组比较的区别是追加机会以及是否收到实际执行后的诊断，不是是否知道公开测试的存在。
这不涉及训练模型参数；反馈只影响后续提示和生成代码。

## 数据边界与预检

这是观察 `070` 之后设计的探索性补充集，必须与原 164 题正式结果分开报告。
不能在运行后只保留 C 赢的题，也不能用隐藏失败信息调整正在修复的模型提示。
各题的 `model_outcomes_used_for_selection=false` 指这些新题在构造时未依据自身模型结果筛选，
不代表设计过程未受此前 `070` 案例启发。

模型只看到每题 `task.json` 的需求和 `workspace/` 中的 solution.py 与公开测试。
参考实现放在 `tools/fixtures/feedback_sensitive/<目录>/solution.py`，
不在任何模型工作区内；隐藏测试也在工作区外。
参考实现仅用于作者检查测试的期望值，不能当成模型提交或模型修复成功的证据。

预检命令不调用模型 API。它分别在断网、只读、资源受限的 Docker 容器中检查：

1. 错误实现的公开和隐藏测试均有断言失败，同时保留已经正确的测试。
2. 参考实现通过所有公开和隐藏测试。
3. 测试完整执行，没有导入错误、超时或文件修改。

```bash
.venv/bin/python tools/preflight_feedback_sensitive.py
```

结果保存为本目录 `preflight.json`，其中包含每个测试函数结果和所有题目/参考文件 SHA-256。
宿主只做文件复制、AST 解析和 Docker 调度，不导入或执行题目的函数与测试。
修改数据后应重新预检，并另开实验批次；保留旧实验结果。

## 运行实验

沿用 `.env` 中现有 DeepSeek 模型和密钥，不需要调整适配器。

```bash
# 20 题 × 3 策略 × 3 次重复 = 180 条策略结果
make experiment TASKS_DIR=benchmarks/feedback-sensitive REPETITIONS=3
```

每题每次重复仍为共享首轮后分叉，上限 A/B/C=1/3/3；整批物理模型调用最多 300 次。
实际调用会因公开通过提前停止而减少。若只需一次试跑，将 REPETITIONS 改为 1（60 条结果，最多 100 次调用）。
结果单独写入新的 `results/experiments/日期_序号/`，沿用现有报告、六张 SVG 和逐轮轨迹。

固定的 temperature=0 可能产生重复答案。调度 SEED 只影响任务/分支顺序，
不控制模型生成随机数；多次重复用于观察稳定性，不能把同题重复当成更多独立题目。
主要比较首轮公开失败后的条件隐藏通过率、C 独赢/B 独赢、公隐差距、回归和新增 token。
如果所有题首轮都通过，应报告天花板现象，不能人为判错或强行让 C 追加修复。
