# 实验设计与验收（精简版）

研究问题：在同样模型、题目和最多三次总提交预算下，公开 pytest 失败诊断能否提高最终隐藏测试通过率？

## 对照

| 策略 | 总提交上限 | 测试与反馈 |
| --- | ---: | --- |
| A：single-shot | 1 | 单次提交后独立评分 |
| B：retry-without-feedback | 3 | 每轮公开测试，通过即停；失败只要求重生成 |
| C：test-feedback | 3 | 与 B 相同，额外提供上轮公开失败诊断 |

每次提交一次模型调用，隐藏结果绝不回传。模型只能提交 solution.py；公开测试不可修改；代码只在断网、资源受限 Docker 中执行，不传入宿主密钥和个人文件。

## 任务与执行

保留全部 50 道正式题，以及三道演示题、30 个测试函数。正式默认每题每策略一次，共 150 个 run、最多 350 次模型调用。额外重复为可选扩展。

冻结题库的来源和测试版本保留，不再下载、筛选或自动拆分。回归按当前 pytest 测试函数的结果变化统计。保留原始错误函数一次隐藏评分，辅助判断原有正确功能；原始公开评分及大型三版本分析不再运行。

## 必须报告

- 首次和最终整题隐藏通过率，最终公开通过率。
- C−B 同题配对差及配对数，仅作描述性比较。
- 代码执行超时、测试函数 passed→failed 回归、公开测试保护违规。
- 实际模型调用数、输入/输出 token、模型/测试/总耗时，及可靠价格下的金额。
- 模型服务/沙箱等异常单列；正常修复失败不能删除或从分母排除。

数据保存为每轮代码、普通 JSONL、原始 CSV。展示只保留一份 Markdown 和四张关键图：隐藏成功率、公隐差距、可靠性、调用与耗时。报告的错误分析由人工选取 3～4 个真实案例填写，不做自动案例筛选或复杂统计图。

## 验收

工程方面须通过 doctor、make check 和 make sandbox-test；保留三组停止规则、隐藏测试隔离、测试保护与实际调用记录。日志无需哈希链，但不能包含密钥。

实验方面需要完成真实 50 题三组结果，并提供公开通过隐藏失败的演示、错误分析与成本。小样本、全部首轮成功、或仅公开测试通过都不能证明反馈有效。

具体配置与操作见 [实验协议](EXPERIMENT_PROTOCOL.md) 和 [操作手册](OPERATIONS.md)。
