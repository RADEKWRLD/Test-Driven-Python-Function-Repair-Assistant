01 / 课题目标与任务范围

评价的是修复效果，
不是补丁看起来是否合理。

要回答的三个问题

  1. 有效性：与只允许重试相比，给出具体报错能否多修好一些题？
  2. 可靠性：修改是否造成超时，或破坏原来已经正确的部分？
  3. 成本：新增成功需要多少次模型调用和多少 token？
最终依据：隐藏测试

公开样例过了，只说明可见检查满足；隐藏测试继续检查同一需求下的其他输入。

15 / 成功案例 070：反馈对应哪一处修改

同一份首轮代码，
B 未修正条件，C 根据报错修正。

B：只有“请再试”，没有具体报错

第 1、2、3 次提交都保留了这一行
min(remaining) if switch else max(remaining)

switch 还是从 False 开始，
所以三次都先取最大值，仍输出 [4, 1, 3, 2]。

公开 FAIL → FAIL → FAIL最终隐藏 FAIL

能确认的是关键条件没改对；不能从日志推测模型内部怎么想。

C：看到了第一项就不相等

E assert [4, 1, 3, 2] == [1, 4, 2, 3]
E At index 0 diff: 4 != 1
第 2 次提交的修改
− min(remaining) if switch else max(remaining)
+ min(remaining) if not switch else max(remaining)

False 加上 not 变 True，先取 min = 1；下一轮取 max = 4。之后继续交替，得到题目要求的顺序。

公开 FAIL → PASS最终隐藏 PASS
B 最后交的代码C 实际收到的报错C 改好的代码

16 / 验收演示：公开通过，隐藏失败

公开通过、隐藏失败的具体案例。

需求将任意连续空白变成一个普通空格，并去掉首尾空白。
normalize_whitespace · 项目已有演示代码
def normalize_whitespace(text):
    return " ".join(text.strip().split(" "))

错误原因

split(" ") 只按普通空格切分，还保留连续分隔产生的空项；再用空格拼回时，多余空格仍然存在，制表符和换行也没有被替换。

符合需求的修改方向是使用无参数 split() 按连续空白切分，再用普通空格拼接。

公开：5 passed
"hello world" → "hello world"
" hello"      → "hello"

这些输入未触及连续或混合空白，错误因此未暴露。

隐藏：5 failed
输入："a   b"
期望："a b"
实际："a   b"

其余失败还包括制表符、换行和 Unicode 空白。

独立演示代码，已在断网、只读 Docker 实测；不是 001 的模型提交，不计入正式胜率。本次验证记录需求与测试定义

20 / 结论与不足

测试反馈显示出帮助，
结论仍受样本和评分口径限制。

  1. 工程成果

    完成补丁提交、隔离测试、失败反馈、有限修正及逐轮留档；三组使用相同模型和可比预算。

  2. 本次实验观察

    C 的最终隐藏通过率为 90.2%，B 为 88.4%，相差 3 题；12 道首轮失败题中分别修好 6 题和 3 题。

  3. 对课题问题的回答

    本批记录支持反馈有帮助的判断，但不代表所有函数都有效。应同时给出真实修复轨迹、隐藏评分和副作用记录。

主要限制

一个模型、一次重复；首轮成功较多，只有 12 题进入纠错。

后续改进

  1. 补充公开测试对边界情况的覆盖，减少公开通过但隐藏失败的情况。
  2. 增加独立重复，继续采用共享首轮比较。
  3. 单独报告 20 道补充题，不按 C 是否成功筛题。

以上改进尚未计入 001 的结果，不作为本次已完成成果。
