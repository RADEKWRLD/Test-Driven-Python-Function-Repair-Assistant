01 / 课题目标与任务范围

评价的是修复效果，
不是补丁看起来是否合理。

要回答的三个问题

  1. 01
    有效性

    与只允许重试相比，给出具体报错能否多修好一些题？

  2. 02
    可靠性

    修改是否造成超时，或破坏原来已经正确的部分？

  3. 03
    成本

    新增成功需要多少次模型调用和多少 token？

本课题的处理范围

1
短小 Python 纯函数

列表、字符串、数值和边界条件；不扩展为多文件项目修复。

2
每题四项材料

需求、错误函数、公开测试、独立保存的隐藏测试。

3
完整保留修复过程

每次提交的代码、模型输入输出、公开报错和最终评分。

4
隔离执行和有限修改

模型只交代码，程序在受限 Docker 中测试；B/C 最多各追加两次。

对应课题书：要解决的问题、任务范围、基础实现要求与对照实验。

03 / 测试管理：公开反馈与隐藏评分

公开测试用于修复过程，
隐藏测试用于最终判定。

它们测的是同一个函数、同一份要求，区别在于模型能否看到，以及什么时候使用。

公开测试 · 修复时可见workspace/tests/test_public.py

文件中直接写输入与期望输出

assert candidate([1, 2, 3, 4]) \
    == [1, 4, 2, 3]
assert candidate([]) == []
assert candidate([0, 2, 2, 2, 5, 5, -5, -5]) \
    == [-5, 5, -5, 5, 0, 2, 2, 2]

三组都会读到这份源码；运行失败时，只有 C 会在下一次请求中收到实际值与期望值。

隐藏测试 · 修复时不可见hidden_tests/test_hidden.py

同一规则，增加未用于修复的输入

INPUTS = [
    [[-5, 0, 5, 10]],
    [[10, 9, 8, 7, 6, 5]],
    [[100, 200, 300, 150, 75, 35, 10]],
    ...
]

for index, arguments in enumerate(INPUTS):
    output = candidate(*copy.deepcopy(arguments))

这个文件只在停止修复后的评分容器挂载；结果不会触发重试。

14 / 案例 070：A 改了什么，为什么仍失败

A 修复了输入副作用，
却保留了取数方向错误。

题目要求从列表中交替取最小、最大、最小、最大……输入 [1, 2, 3, 4] 应得到 [1, 4, 2, 3]。
原始 solution.py · 完整函数冻结题目文件
def strange_sort_list(lst):
    '''
    Given list of integers, return list in strange order.
    Strange sorting, is when you start with the minimum value,
    then maximum of the remaining integers, then minimum and so on.

    Examples:
    strange_sort_list([1, 2, 3, 4]) == [1, 4, 2, 3]
    strange_sort_list([5, 5, 5, 5]) == [5, 5, 5, 5]
    strange_sort_list([]) == []
    '''

    res, switch = [], False
    while lst:
        res.append(min(lst) if switch else max(lst))
        lst.remove(res[-1])
        switch = not switch
    return res

A 的首轮提交

相对原始代码的实际修改attempt 01
+ remaining = list(lst)
− while lst:
+ while remaining:
− min(lst) if switch else max(lst)
+ min(remaining) if switch else max(remaining)
− lst.remove(res[-1])
+ remaining.remove(res[-1])
改对了复制列表后再删除，不再修改调用者传入的 lst。
没改到switch=False 仍走 else max，第一步继续取 4。
期望输出[1, 4, 2, 3]
A 实际输出[4, 1, 3, 2]
公开 FAIL隐藏 FAILA 到此停止

16 / 验收演示：公开通过，隐藏失败

公开通过、隐藏失败的具体案例。

需求将任意连续空白变成一个普通空格，并去掉首尾空白。
normalize_whitespace · 项目已有演示代码
def normalize_whitespace(text):
    return " ".join(text.strip().split(" "))

错误原因

split(" ") 只按普通空格切分，还保留连续分隔产生的空项；再用空格拼回时，多余空格仍然存在，制表符和换行也没有被替换。

符合需求的修改方向是使用无参数 split() 按连续空白切分，再用普通空格拼接。

公开：5 passed
"hello world" → "hello world"
" hello"      → "hello"

这些输入未触及连续或混合空白，错误因此未暴露。

隐藏：5 failed
输入："a   b"
期望："a b"
实际："a   b"

其余失败还包括制表符、换行和 Unicode 空白。

独立演示代码，已在断网、只读 Docker 实测；不是 001 的模型提交，不计入正式胜率。

17 / 结论与不足

两个模型得到一致方向，
测试反馈组都优于无诊断重试。

  1. 工程成果

    同一修复协议已经接入 DeepSeek 与百炼 Qwen，并保留隔离测试、逐轮代码和评分证据。

  2. 跨模型观察

    共同 160 题中，C 相对 B 在 DeepSeek 多通过 3 题，在 Qwen 多通过 5 题。

  3. 对课题问题的回答

    两批记录都支持具体报错有帮助的判断。结论来自隐藏评分，不只依据公开测试。

主要限制

每个模型只有一次重复。进入纠错的题仍较少，Qwen 另有 4 道基础设施异常。
