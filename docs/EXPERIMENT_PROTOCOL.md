# 课题 07 实验协议（精简版）

修复协议仍为 `shared-public-test-stopping-v3`，三组预算不变。报告配置另记 `implementation=course-simple-v2`，采用直观目录命名，与旧布局批次分开保存。

## 任务与三组

正式保留仓库中已冻结的 50 道 FeedbackEval-HumanEval Python 修复题；错误候选来自 FeedbackEval，需求及公隐测试沿用 HumanEvalPack 的隔离拆分。50 个候选均已在 Docker 中验证为初始公开测试失败且无超时。正式运行时不下载、重新筛选或拆分测试；正确答案和预生成反馈不进入题目目录。题库来源、commit、测试 revision 和候选哈希均保留。三道演示题共 30 个测试函数，用于演示和流程检查。

| 组 | 策略 | 首次提交 | 最多追加 | 总上限 | 失败反馈 |
| --- | --- | ---: | ---: | ---: | --- |
| A | single-shot | 1 | 0 | 1 | 无后续修复 |
| B | retry-without-feedback | 1 | 2 | 3 | 只要求重新生成，不提供诊断 |
| C | test-feedback | 1 | 2 | 3 | 上轮公开 pytest 的失败输出 |

B/C 运行相同公开测试并在通过时停止。B 从继续重试获得隐含失败信号，因此应称“无详细诊断”，不能称完全无反馈。A 提交后独立评分。每次提交只调用一次模型，三组均只能修改 solution.py。

默认重复次数为 1：50×3=150 个 run，调用预算至多 50×(1+3+3)=350 次。重复实验属于可选扩展，必须显式配置，不自动执行。

## 固定条件和安全要求

- 正式环境固定为本机 Ubuntu/WSL2、Python 3.12+、Docker，不扩展原生 Windows。
- 正式实验仅使用 DeepSeek API；同一批次的三组必须使用同一模型、endpoint、参数和资源预算。
- 当前 DeepSeek 显式关闭思考模式，temperature=0。调度 seed 只打乱任务顺序，不控制模型采样或服务商升级。
- 候选代码只在断网、资源受限的 Docker 容器运行；rootfs/workspace 只读，不传密钥、个人目录、Docker socket 或原始题库。
- 模型没有 shell，只能提交完整 solution.py。公开测试的只读挂载、SHA-256 校验与文件白名单保持原有实现。
- 隐藏测试不进入模型上下文；仅在修复结束后由独立评测容器挂载，隐藏结果不回流修复。

## 评分和回归

公开/隐藏测试均通过 pytest 执行，最终评分用 JUnit XML 记录现有测试函数的 passed、failed、error、timeout、not_run。没有运行时逐断言追踪，未执行结果不能算通过。

保存首次与最终提交的公开/隐藏评分；只有一次提交时复用其结果。保留一份原始错误函数快照，只执行一次轻量隐藏评分，判断原本通过的测试函数是否被最终修复改坏；不再评估原始公开测试或输出全面三版本对比系统。

主指标：最终隐藏测试全部通过的有效 run / 该组有效 run。正常用尽预算仍失败和候选代码超时留在分母中；模型服务/沙箱等基础设施异常单列。

同时报告第 1/2/3 次提交后的累计公开通过率、首次隐藏通过率、最终公开通过率、超时率、功能回归与测试保护违规。功能回归保留两类证据：原始→最终、首次→最终的同一个测试函数 passed→failed。error/timeout/not_run 单列，不能冒充已经证实的断言回归。

C−B 比较只使用同题同重复编号下都有有效结果的配对，报告最终隐藏通过率差和配对数。仅作描述性解释，不生成复杂 bootstrap 或显著性图；没有观察到收益也必须如实报告。

## 日志、成本和简单继续执行

- 每轮保留代码、请求/响应、公开反馈与成本，events.jsonl 是普通追加日志，不再声称具有防篡改能力。
- 默认保存于 results/experiments/日期_序号/，北京时间日期、当天递增编号；逐题记录按组保存在 runs/group_a/、runs/group_b/、runs/group_c/，其下日期_实验序号_执行序号为独立任务目录，编号跨组不重复。代码放在 original_code/、repair_attempts/01/ 等目录。重做中断任务分配新序号，保留原目录证据。单题调试也在 results/runs/ 下按 group_a、group_b、group_c 分类，兼容读取旧的平铺目录。
- 保留输入/输出 token、缓存用量、调用数、模型延迟、测试/整题耗时和每成功 run 的 token；实际用量缺失或没有成功 run 时保持未知。
- 金额只按用户核实的供应商、模型、日期、币种及单价计算。缓存差价如适用则保留，否则不启用。没有价格/用量时金额为 null，不填零；不开发预测或优化模块。
- 每个 run 结束后立即写 summary.json 与 results.jsonl，异常不会阻止后续题目。
- 简单继续执行只校验 config.json 基本配置并按任务+策略+重复编号跳过 results.jsonl 中已有结果，包括失败；没有完整状态机、进度锁、代码/镜像哈希审计或自动错误重试。
- 同一目录不可同时启动多个进程。代码、题库、测试或镜像变化后另开批次，保留旧结果。中断时尚未保存的任务会在继续时重新执行，可能有未知 API 费用，需人工核对日志。

## 最终报告与验收

只生成一份 report.md、原始/汇总/测试函数 CSV 和五张 SVG：逐轮累计公开通过率、隐藏成功率、公隐差距、回归与超时、调用量与耗时。JSON 是程序保存和重建报告所需的原始记录，不是额外展示格式。没有 HTML、自动案例报告或自动下载筛题工具。

在 report.md 人工选取 3～4 个真实案例，记录需求、初始缺陷、逐轮代码变化、公开反馈、隐藏结果与原因。公开通过但隐藏失败的演示必须保留；没有超时/回归时说明未观察到，不编造案例。

工程验收须通过 doctor、make check 与 make sandbox-test。正式效果仍需实际运行 50 题三组一轮，本次精简不自动启动付费实验。
